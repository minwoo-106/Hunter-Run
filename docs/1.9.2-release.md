# Hunter Run 1.9.2 / 빌드 65

## 변경

몬스터와 보스를 장비 획득 순서에 맞춰 조정했습니다. 최종 보스는 첫 공략 전에 얻을 수 있는 철갑 파쇄추·재갑 전술화·공백 인장을 기준으로 약 5km의 유효 교전을 목표로 합니다. 귀환 장비는 첫 공략 이후 보상이라 기준에서 제외했습니다. 레벨을 등급이나 해금 진행도와 동일시하지 않습니다.

기존에 시작한 보스는 저장된 최대 HP와 남은 HP를 그대로 사용합니다. 남은 HP를 비율로 늘리지 않으며 이미 완료한 보스를 되살리지 않습니다. 진행 중인 일반 활동도 저장된 전투 규칙을 보존합니다. 새 HP는 다음 활동과 새 보스 공략에 적용되고, 누적 보스 공략은 여러 활동에 걸쳐 계속할 수 있습니다.

실제 적용값과 장비별 거리는 [전체 전투표](1.9.2-combat-balance.md)를 참고하세요. 거리는 조우·안내·GPS 보류 구간을 제외한 공격 거리이며 실제 운동 총거리와 같지 않습니다. 최종전의 기존 안전 걷기 대안도 유지합니다.

누적 공략은 주요 보스·승급 심사·재전 보스에 적용됩니다. 일반·정예·선발대는 기존과 같이 활동이 바뀌면 HP를 초기화하며, 업데이트 당시 진행 중인 활동 자체는 기존 스냅샷을 보존합니다.

## 검증

- 로컬 Swift 자동 테스트 309개 통과.
- 실제 RunEngine 센서 입력 재생 12개 통과: 75m 경계, 다중 공격, 오버킬, 중복 정산, 일반 초기화·보스 누적, pause/resume, GPS 불량·정지와 앱 복구.
- 실제 카탈로그와 CombatEstimate/DistanceBattle로 37종 × 9장비 × 8레벨 = 2,664개 조합 검산. 처치 직전 1m 생존, 마지막 1m 처치, 처치 후 추가 공격 무효 확인.
- 12종 보스·변이·심사 각각의 기존 HP 1%/50%/100% 저장 복구와 토벌·중복 정산 방지 확인.
- 이전 1.9.1 규칙의 72개 기준표도 유지해 구세션 계산 보존 검증.
- 콘텐츠·승인 음성·생활 모션 검사 통과.
- iPhone Release 컴파일 및 iOS 18.5 시뮬레이터의 iPhone 16 Pro·iPhone SE(3세대) 화면 검사 총 22개 통과. 각 기기 실제 앱 캡처 21장, 총 42장 확보. 장비 시험실과 일시정지 전투 화면을 직접 확인했습니다. 실제 야외 GPS와 운동 체감은 이번 자동 검증에 포함하지 않습니다.

첫 아이폰 검사 실행에서는 iPhone 16 Pro의 앞선 6개 테스트가 `app.launch()`에서 `Timed out while acquiring background assertion`으로 실패했고 뒤의 5개는 통과했습니다. 실패 녹화에서도 게임 화면이 아닌 시뮬레이터 홈 화면에 머물렀습니다. 재현 명령은 `bash scripts/check-ios-layout.sh growth-experience`이며, 앱 코드와 검증 기준을 바꾸지 않고 동일 커밋을 새 실행 환경에서 재검증한 두 번째 실행에서 22개 모두 통과했습니다. 최초 실패는 별도로 기록하며 통과로 처리하지 않습니다. 정확한 시스템 내부 지연 원인까지 확정한 것은 아닙니다.

거리표 HTML은 내장 데이터, 레벨·검색·공격 횟수 선택 및 복사 내용을 별도 자동 검사했습니다. 이번 환경의 브라우저 도구는 로컬 HTML 열기를 허용하지 않아 HTML 화면의 직접 시각 검수는 수행하지 못했습니다. 앱 화면 검증과는 별개입니다.

## 재현

```sh
swift test
swift run HunterDebugRunner --output .build/combat-replay
swift run HunterDebugRunner --balance-report --output .build/balance-review
python3 scripts/build-balance-review.py .build/balance-review
```

생성되는 HTML은 레벨·거리/공격 횟수/피해 선택, 이름 검색, 현재 표와 전체 표 복사, 텍스트 저장을 제공합니다. 외부 연결이나 사용자 저장 파일을 사용하지 않습니다.
