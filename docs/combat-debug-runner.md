# 전투·성장 자동 검증 실행기

이 작업은 확정된 3차 규칙의 구현 전 검증 기반이다. 실제 `RunEngine`, `Settlement`, `BossCampaign`, 장비 계산부를 호출한다. 별도의 전투 계산을 웹 화면에 복제하지 않는다. 일반 앱에서 규칙을 자동 활성화하거나 실사용 저장 파일을 이행하지 않는다.

## 실행

저장소 위치에서 Swift 실행 환경을 사용한다.

```sh
swift test --jobs 4
swift run HunterDebugRunner --output .build/combat-replay
python3 scripts/build-combat-replay-review.py .build/combat-replay
```

`.build/combat-replay/index.html`을 열면 대표 시나리오를 선택하고 입력 단계별 HP·75m 누적·공격·실제 피해·EXP·일시정지·안내 발생 시점을 볼 수 있다. 서버나 외부 파일 요청이 없어 인터넷 연결과 `127.0.0.1` 서버가 필요 없다. 이 화면은 결과 감상용이며 음성 파일을 재생하지 않는다.

입력을 바꿔 재검증할 때는 화면의 ‘현재 시나리오 입력 저장’을 사용한다.

```sh
swift run HunterDebugRunner --scenario 입력파일.json --output .build/custom-replay
python3 scripts/build-combat-replay-review.py .build/custom-replay
```

실행기는 프로필 값의 메모리 복사본과 입력 파일만 사용한다. 저장소 검증 함수는 호출하지만 실제 게임 저장소의 읽기·쓰기 함수는 호출하지 않는다. 출력은 사용자가 지정한 검증 결과 경로에만 기록한다. 실사용 저장 경로를 출력 경로로 지정하지 않는다.

## 입력 구조

| 항목 | 의미 |
|---|---|
| profile | 검증용 레벨·EXP·장비·보스 진행도 |
| session | 초기 세션과 전투·목표·공격력 스냅샷 |
| content | 해당 세션의 임무 자료 |
| operations | 재생할 명령의 순서 |
| expected | 마지막 단계에서 반드시 만족할 고정 기대값 |

명령은 `frame`, `pause`, `resume`, `instructionFinished`, `recover`, `finish`, `settle`, `beginSession`이다. `frame`에는 센서 입력이 필요하고, `beginSession`에는 다음 세션과 임무 자료가 필요하다.

센서 입력의 `timestamp`는 초, `speed`는 m/s, `distance`는 직전 입력 이후 추가 거리(m)다. `distanceDuration`은 GPS가 묶어서 전달한 거리가 대표하는 시간(초)이다. `movement`에는 `running`, `walking`, `stationary`, `vehicle`, `unknown`을, `signal`에는 `good`, `degraded`, `unavailable`을 사용한다. 세션과 같은 시간축으로 입력하며, 중복·역순·긴 공백은 정상 공격 구간으로 인정하지 않는다.

`recover`는 세션과 프로필을 실제 직렬화·복원한 후 기존 복구 정책대로 일시정지한다. 다음 세션의 초기 값은 입력에 명시한다. 보스의 실제 누적 정산과 프로필에서 다음 보스 상태를 생성하는 경로는 별도 회귀 테스트에서 검증한다.

검증용 Lv.15의 EXP 4250은 합성 예제다. 사용자의 실제 총 EXP를 확보했다고 주장하거나 실제 저장을 수정하지 않는다. 장비 네 개는 사용자가 알려준 실제 착용 목록이다.

## 자동화 범위

| 요청 | 검증 |
|---|---|
| 75m 누적 | 74/75m 경계·잔여 거리·0.1/0.05m 반복·무작위 분할 입력 |
| 다중 공격 프레임 | 225m 묶음의 3회 공격·다중 보스 공격 |
| 오버킬 | 실제 피해를 남은 HP 이하로 제한·토벌 후 잉여 거리 폐기 |
| HP0 이후 정산 | 후속 센서·복구·재개·중복 세션 정산 차단 |
| 일반 몬스터 | 미완료 전투를 끝낸 뒤 새 세션은 HP 초기화 |
| 주요 보스 | 부분 피해 정산·저장 복원·다음 세션 누적·첫 토벌 보상 |
| 몬스터 EXP | 고정 보상·미토벌 보상 없음·중복 기록 및 정산 방어 |
| 장비 공격 횟수 | 승인된 8개 레벨×9개 장비 조합의 72행과 실제 계산 일치 |
| 기존 세이브 | Lv.15 및 EXP·장비·등급·스토리·시설 보존·300개 진행값·고레벨 공격 하한 |
| 일시정지·복구 | 시간/거리 정지·복귀 첫 입력 기준점·정지를 가로지르는 GPS 묶음 차단 |
| GPS·움직임 | 불량·정지·걷기·차량·자동 일시정지·복귀·안내 중 GPS 거리 차단 |

일반 거리 전투는 정상 GPS와 달리기 판정일 때 공격한다. 걷기·GPS 불량은 해당 몬스터와 공격 잔여 거리를 유지하면서 공격을 보류한다. 이것은 검증 대상 규칙이며, 실제 움직임 분류기의 모든 오판을 없앴다는 의미는 아니다.

이번 검증에서 종료된 세션의 재개, 수동 일시정지를 가로지른 거리, 활동 종료 프레임의 마지막 공격 누락, 안내 중 이동의 공격 전환, 소수 거리 오차, 중복 전투 기록의 보상 문제가 재현되어 수정됐다. 기존 기능 테스트도 함께 실행한다.

## 과거 로그

기존 활동 보고는 요약값 중심이며 초 단위 원본 센서 열이 없다. 요약 거리·평균 페이스만으로 원래 GPS 흐름을 복원하지 않는다. 빠른 걷기 제보 사례는 합성 입력으로 명시해 재현했다. 이제 `SensorFrame`을 직렬화할 수 있으므로 향후 확보한 입력 열을 같은 `operations` 구조로 변환하면 재생 가능하다. 자동 위치 기록 수집을 앱에 추가한 것은 아니다.

## 남겨 둘 실제 기기 확인

- 75m 공격 간격과 몬스터 한 마리의 운동 길이 체감
- 안내 음성의 겹침·간격·잠금 화면에서의 실제 전달
- GPS 흔들림 및 실제 달리기·빠른 걷기 분류
- 러닝 도중의 전체 흐름
- 실제 iPhone의 백그라운드·오디오 중단·센서 콜백 전달 확인

계산 오류는 먼저 재생 입력으로 고정하고 회귀 테스트에 추가한다. 같은 오류를 확인하려고 반복 야외 활동을 요구하지 않는다. 기기 확인도 전투 공식 재검증과 분리한다.

## 일반 앱 반영 전 남은 범위

새 규칙은 `combatRules`와 `growthEconomy`가 있는 검증 세션에서만 동작한다. 승인된 수치를 실사용 앱에서 켜는 이행·승급 심사/변형 보스의 별도 임무 연결·새 전투 UI·공격 음성 정책 등은 후속 구현 범위다. 앱 버전·배포·실사용 세이브는 이번 작업에서 변경하지 않았다.

새 회귀 검증 절차는 소스·테스트·수치 자료 변경 시 자동 실행되도록 준비했다. 로컬에서 실행을 확인했고, 원격 작업 실행이나 업로드는 하지 않았다.
