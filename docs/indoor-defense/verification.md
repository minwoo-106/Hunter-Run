# 검증 상태와 출시 전 승인

기준일: 2026-10-07. 이 문서는 완료된 확인과 남은 확인을 구분한다.

## 최종 승인 이후 갱신

사용자가 마지막 10개 수정 음성을 모두 승인하고 이미지·음성 전체 통과 및 나머지 작업 진행을 명시했다. 아래 승인 전 기록은 제작 이력이다. 최종 음성 151개와 이미지 9개의 해시는 `reviews/2026-10-07-final-approval.json`에 고정했고 수정 WAV 47개를 앱에 반영했다. 최종 오디오 36.1 MiB, 이미지 21.3 MiB다. `validate-defense.py`는 이 승인 해시까지 검사하며 설치 패키지 검사에서도 151개 WAV를 전부 대조한다.

최종 자산 반영 후 전체 Swift 테스트 226개가 다시 통과했다. Codemagic #56에서 iPhone 컴파일과 큰/작은 화면 UI 검사 총 10개, 내려받은 IPA의 자산·데이터 검증까지 완료했다. 현재 iOS 빌드 상태와 설치 결과는 [1.7.0 안내](../1.7.0-release.md)를 기준으로 확인한다. GitHub Actions는 계정 결제/사용 한도로 서버 시작 전에 중단되어 Codemagic으로 전환했다.

## 초기 제작·검토 이력

- 전체 Swift 패키지 테스트 226개 통과, 실패 0개. WSL/Linux Swift 6.2에서 실행했다.
- 캠페인 전용 테스트 6개: 30회×3강도 시간 구성, 일시정지/재개/긴 공백, 30회 정산과 중복 지급 방지, 이전 세이브 읽기/쓰기, 잘못된 진행과 회차 건너뛰기 거부, 실제 legacy indoorTreadmill 기록을 가진 세이브의 캠페인 완료 후 기록 보존.
- 새 앱 화면과 연결 파일의 Swift 문법 검사. iOS SDK 타입 검사와 다르다.
- 승인 전 검토용 일러스트: 주요 회차 7장, 30회차 비하인드 1장, 전용 배경 1장. 잘못 사용한 예전 얼굴 기반 컷은 포함하지 않는다.
- 오디오 제작은 기존 승인된 합성 오퍼레이터 음성을 참고한 로컬 합성이다. 새 발화의 음색·억양이 모두 같다고 자동 판정하지 않는다.
- 전체 콘텐츠 검사 통과: 신규 음성 151개, 이미지 9개와 기존 앱 자산 연결 확인. 신규 음성 38.7 MiB, 그림 20.9 MiB. 운동 안내 최장 8.23초로 최단 준비 20초보다 짧다.
- 오프라인 검토 페이지를 Chrome에서 확인했다. 151개 음성 필터·검색, 이미지 확대, 로컬 음성 재생, 이미지 로딩, 문서 링크, 390px 화면의 가로 넘침 없음, JavaScript 오류 없음. 이것은 검토 페이지 검증이며 iOS 앱 UI 검증은 아니다.
- 음성 검토 체크 기능 확인: 좋아요/목소리 다름/억양·발음 수정, 문장별 메모, 새로고침 후 보존, 수정 대상 필터, 기준 목소리 재생, 복사 목록과 JSON 다운로드. 별도 테스트 브라우저에서 확인해 사용자 체크에 영향을 주지 않았다. 음성 파일이 교체되면 이전 파일의 승인 표시를 재사용하지 않는다.

## 음성 확인 방법

검토 페이지 상단의 ‘음성’을 누르면 한 음성씩 보는 집중 화면으로 전환한다. 카테고리와 진행도는 상단, 판정과 이전/다음은 하단에 고정한다. ‘좋아요’는 기본적으로 다음 음성으로 이동하고, 수정 판정은 메모 입력을 위해 현재 음성에 머문다. ‘현재 시점부터 달라짐’은 재생 위치를 메모에 넣는다. 카테고리 마지막 음성의 다음 버튼은 다음 카테고리로 이동한다. ‘전체’와 ‘수정 요청’을 함께 선택하면 모든 회차의 수정 대상을 모아본다.

체크 내용은 해당 브라우저에 보관되며 다른 PC/브라우저나 이 채팅으로 자동 전송되지 않는다. ‘체크 내보내기 / 가져오기’에서 ‘체크 목록 다운로드’로 받은 `HunterRun-voice-review.json`을 채팅에 첨부하거나 ‘복사할 목록 보기’의 내용을 전달한다. 가져오기는 이미 작성한 체크를 덮어쓰지 않는다. 브라우저가 로컬 저장을 막으면 화면에서 알리며 다운로드/복사로 보관할 수 있다. 단순 재생을 승인으로 간주하지 않는다.

2026-10-07 검토 화면 개편은 기존 파일 경로와 저장 키를 유지한다. 음성 교체 후에는 기존 승인을 해제하되 이전 수정 메모를 보여주며, 재판정 시 이전 해시와 메모를 이력으로 보관한다. 사용자 브라우저의 실제 체크에는 접근하지 않았다. 별도 가상 체크로 보존, 재개, 판정 후 이동, 시점 메모, 카테고리 이동, 수정본 이력, 내보내기, 비파괴 가져오기, 저장 실패 처리를 Node에서 확인했다. 개편 화면의 실제 브라우저 배치 검증은 아직 하지 않았다. 위 Chrome 검증 기록은 개편 전 화면에 대한 것이다.

## 검사 도구

- `scripts/validate.py`: 기존 콘텐츠와 신규 캠페인 전체 자산 검증.
- `scripts/validate-defense.py`: 30개 회차, 대사와 음성 151개 대응, WAV PCM 규격/길이/피크/해시, 이미지 9개 연결. 가장 짧은 동작 준비 20초 안에 안내가 끝나도록 운동 지시는 18초 미만을 요구한다.
- `scripts/build-defense-review.py`: 원본 얼굴 비교, 일러스트 확대, 대사 번호별 음성 재생, 전체 설계 문서를 포함한 오프라인 ZIP. IPA를 만들지 않는다.
- `scripts/build-defense-review.py --repair-dir <수정본 폴더>`: 사용자 체크를 기본값으로 포함하고, 수정본만 모아 수정 전/후 음성을 비교한다. 앱의 음성 파일을 교체하지 않고 검토 패키지에만 수정본을 넣는다. 해당 폴더의 수정 대상이 모두 준비되지 않거나 해시가 다르면 패키지 생성을 거부한다.
- `node scripts/test-defense-review-state.cjs`: 가상 체크를 이용한 보존·이동·내보내기와 수정본 기본 필터, 이전 음성 연결, 새 판정 우선 적용 검사. 실제 브라우저 화면/청감 검증은 아니다.
- `scripts/check-ios-layout.sh defense`: 승인 후 Mac에서 실행할 작은/큰 iPhone UI 검사 경로. 실내 진입 교체, 3강도, 일시정지/배경 복귀, 이어하기, 최종 회차 보고와 별도 비하인드 버튼 검사를 준비했다.

## 현재 남은 확인

- 이미지·음성 검토는 최종 승인으로 완료했다. 수정 대상이던 파일을 포함해 승인 해시를 앱 자산과 대조했다.
- Xcode iPhone Release 컴파일은 통과했다. 첫 UI 검사에서 저장 후 이전 준비 화면에 남는 문제가 발견되어 캠페인 허브로 돌아오도록 수정했다. 수정본은 큰/작은 화면 검사를 모두 통과했다. 실제 IPA 검증 결과는 [1.7.0 안내](../1.7.0-release.md)에 기록한다.
- 실제 iPhone의 전체 24분 운동, 화면 잠금·전화·이어폰 분리 후 복귀, 발열·메모리·배터리, 작은 화면/큰 글씨 사용감.
- 신체 동작 검증. 현재는 안내 완료 시간만 저장하며 실제 운동량·칼로리·자세를 인증하지 않는다.

## 승인 경계

이미지·음성 승인 전에 IPA를 배포하지 않았으며, 사용자의 전체 승인 이후 1.7.0 빌드·설치 검증을 진행한다. 검토 페이지의 HTML/ZIP은 앱 설치 파일과 별개다. 새 미승인 음성을 추가 합성하지 않는다.

## 승인 후 순서

1. 승인된 이미지·음성을 파일별로 확정한다. 지적한 파일만 수정하고 다시 확인한다.
2. iOS 컴파일 및 큰/작은 화면 UI 검사를 실행한다. 실패하면 수정 후 관련 검사를 다시 한다.
3. 설치용 IPA를 만들어 실제 iPhone 검증으로 넘긴다.
4. 실제 24분 수행 결과를 반영하고 정식 공개 품질을 확인한다.

운동 안내 검수는 표준 강도 1회차를 우선한다. 준비 4분이 충분한지, 회복에서 동작으로의 전환을 눈으로 보지 않고 알 수 있는지, 대사가 과하지 않은지, 두 번째 작전을 하고 싶어지는지 확인한다.
