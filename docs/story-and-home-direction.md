# 메인 스토리와 오퍼레이터 홈 연출 제안

2026-09-13 제안 초안. 현재 배포본0.11에는 적용하지 않았으며, 아래 인물명·분량·해금 시점은 확정값이 아니다.

## 현재 기반
- 홈의 home.stories 버튼에서 협회 통신6편에 접근할 수 있다.
- 실제 활동/협회 성장/보스 토벌에 따른 잠금, 읽음 표시, 다시 보기와 일부 음성 요약이 있다.
- 현재 본문은 문서형이다. 장면별 대화 진행, 대화 중간 이어보기, 잠금/완료 개수 집계는 추가해야 한다.
- 홈 배경과 OperatorCutout은 이미 분리되어 있으나 캐릭터 내부 레이어와 눈 표정 리소스는 없다.

## 제안하는 경험
홈에는 고정된 '스토리' 버튼과 새 이야기 배지를 둔다. 홈 말풍선은 다음 이야기/새 발견/귀환 상황에 맞는 짧은 대사로 바뀐다. 진행은 사용자가 버튼을 눌렀을 때만 시작한다.

스토리는 기존 홈 배경·오퍼레이터 위에 대화창을 펼치는 방식이다. 화자 이름, 짧은 대사, 다음/로그/닫기를 제공한다. 글자 표시 중 탭은 문장 전체 표시, 다음 탭은 다음 대사로 구분한다. 자동 넘김은 선택 기능이다. 강제 화면 전환이나 활동 중 스토리 팝업은 없다.

목록에는 전체/읽음/새 이야기/잠김 개수를 표시한다. 먼 후속화는 제목 대신 '???'와 잠금을 보여주고, 바로 다음 이야기에는 스포일러가 적은 목표와 진행도를 표시한다. 다시 보기는 보상과 해금을 재발생시키지 않는다. 보던 장면은 저장해 이어볼 수 있다.

## 세계관과 이야기 흐름 초안
오퍼레이터 이름은 최초 등록에서 사용자가 정한다. 기존 '서윤'은 미입력 시 제안할 수 있는 가칭이며 고정 인물명으로 확정하지 않는다. 갑작스러운 게이트 발생 이후 대한민국 헌터협회가 잔향에 반응하는 현장 인원을 모집했다. 주인공은 임시 지부에 배정된 신규 헌터이며, 오퍼레이터와 평범한 활동 속 관측 기록을 모아 원인을 추적한다. 실제 위험 지역이나 특정 좌표로 이동하도록 요구하지 않는다.

- 프롤로그: 첫 만남, 게이트와 공명 현상, 신규 헌터 등록, 첫 관측 요청.
- 1장: 반복되는 신호, 최초 개체 조사, 지부 확장, 첫 게이트 관측.
- 2장: 다크엘프 정찰 흔적과 서큐버스 환영. 서로 다른 개체가 같은 잔향에 반응한다는 단서.
- 3장: 경계의 군주와 공허의 사서. 누적 토벌을 통해 게이트 발생에 관한 하나의 답을 얻고 v1의 중심 사건을 마무리한다.
- 후속 수집: 미해결 조사와 인물 대화. 본편의 결말을 제공한 뒤에도 선택적 토벌/수집을 이어갈 수 있다.

분량 초안은 프롤로그 포함12~16개 짧은 장면. 각 장면은 대략1~2분. 편수로 억지로 시간을 늘리지 않고 조사와 성장 목표에 맞춰 조정한다. 기존6편의 내용과 읽음 기록은 보존/이관한다.

## 성장 연계
경제와 이야기 해금을 함께 설계한다. 단순 화폐 누적 대신 누적 활동량, 개체 조사, 협회 시설, 평가, 보스 성과를 조합한다. 첫 발견은 도감, 추가 조사는 분석·후속 의뢰, 토벌 성과는 소재·장비와 연결한다.

스토리 읽기 자체는 자원 획득이나 운동 진행도의 원천이 아니다. 일상 활동은 언제든 가능하다. 스킵해도 진행 목표가 사라지지 않으며 다시 볼 수 있다. 콘텐츠 해금은 명시한 게임 조건으로 결정하고, 이야기 읽기를 강제 장벽으로 만들지 않는다.

여러 조건을 한 번에 충족하면 새 이야기를 대기열에 넣고 순서대로 열람할 수 있게 한다. 자원을 소비하거나 장비를 바꿔도 이미 해금한 이야기는 다시 잠기지 않는다. 모의 활동으로 실제 이야기를 해금하지 않는다. 기존 사용자의 해금·장비를 성장 개편으로 회수하지 않는 이관안을 마련한다.

## 홈의 2D 레이어 모션
- 몸통의 약한 호흡, 느린 어깨 움직임.
- 열린 눈/반쯤 감은 눈/감은 눈 리소스로 불규칙한 간격의 눈 깜빡임.
- 이야기 감정에 따른 기본/미소/걱정 표정 전환.
- 필요하면 머리카락/넥타이의 작은 움직임과 배경 광원 연출.

현재 컷아웃으로 약한 움직임은 가능하지만 자연스러운 눈·머리·몸의 독립 동작은 동일 인상을 유지하는 레이어 리소스 제작이 필요하다. 얼굴·손·실루엣 일관성을 검수한다. 전체 그림을 크게 확대·축소하는 연출은 피한다. 얼굴 회전/입모양 동기화/완전한 리깅은 이번 기본안에 포함하지 않는다.

홈을 떠나거나 화면이 꺼지면 연출을 멈추고 iOS 동작 줄이기 설정을 반영한다. 활동 화면의 센서·안내와 경쟁하지 않도록 분리한다. UI 조작영역과 화면 안전영역은 기존대로 유지한다.

## 구현 순서
1. 페이스·센서 정확도 개선과 별개로 세계관/장별 목표/해금 흐름을 확정한다.
2. 기존 통신을 장면 데이터로 옮기고 홈 버튼·목록 집계·대화·재열람·이어보기를 구현한다.
3. 경제·조사 진행도와 해금 조건을 연결하고 기존 저장 이관/중복 보상 방지를 검증한다.
4. 표정·레이어를 제작해 호흡/깜빡임을 적용하고 기기에서 배터리·프레임·이미지 일관성을 확인한다.
5. 대사 확정 후 필요한 부분만 음성을 추가한다. 홈의 기본 대화는 텍스트 중심으로 한다.

## 사용자 추가 요청 · 등록/퀘스트/승급 심사

2026-09-13 추가 방향. 아래는 기획 반영이며 배포본0.11에 아직 구현되지 않았다. 보상액·필요횟수·심사보스 이름은 밸런스 설계 후 확정한다.

### 첫 등록과 이름
- 헌터 닉네임과 오퍼레이터 이름을 입력한다. 확정 전에 두 이름이 들어간 소개 문장을 미리 보여준다.
- 스토리의 화자명/소개/홈 대사에 입력 이름을 사용한다. 조사와 '이에요/예요' 처리를 지원하고 이름 변경 후 과거 대사도 현재 이름으로 표시한다.
- 기존 이용자는 기존 헌터명을 유지하고 오퍼레이터 이름만 추가로 설정할 수 있게 한다. 진행도를 초기화하지 않는다.
- 임의 이름을 현재 사전 제작 음성이 그대로 발음할 수는 없다. 텍스트 이름 치환은 구현 범위에 포함하며, 기존 승인 음성은 '헌터님', '전담 오퍼레이터' 같은 공통 호칭을 사용하는 안이다. 이름을 읽는 커스텀 음성은 별도 결정 사항이며 실시간TTS/서버를 자동 도입하지 않는다.

### 스토리 퀘스트
- 메인 조사 퀘스트: 후속 스토리와 새 의뢰/콘텐츠 조건에 연결한다.
- 토벌 의뢰: '잔향 늑대10마리'처럼 누적 토벌을 목표로 추가 경험치/자원을 지급한다.
- 승급 심사: 자격 충족 후 별도 심사 임무를 통해 등급을 올린다.
- 홈 스토리 카드에 다음 목표와 진행도를 표시하고 퀘스트 상세에서 보상/조건을 확인한다. 진행 안내는 활동 중 화면 조작을 요구하지 않는다.
- '조사/발견'과 '토벌'을 별도 조건으로 취급한다. 토벌 수는 실제 적HP를0으로 만든 결과만 센다. 모의 활동·단순 피해·중립 종료는 토벌에 포함하지 않는다.
- 수락 버튼 누락 때문에 이미 달성한 기록을 놓치지 않도록 누적형 퀘스트는 저장된 실제 이력을 반영한다. 후속 특정 임무형 퀘스트는 시작 시점을 명시한다.
- 보상 지급/진행 저장은 중복 정산되지 않게 처리한다. 재열람·앱 재실행·백업 복원으로 같은 완료 보상을 다시 받을 수 없어야 한다.
- 첫 이야기를 무작위 늑대10회 출현에 묶지 않는 안을 우선 검토한다. 초반은 첫 조사/첫 토벌로 짧게 진행하고10마리 목표는 중기 의뢰로 배치한다. 관련 의뢰를 선택하면 목표 개체를 만날 기회를 제공해 무작위 출현 대기를 줄인다.

### 승급 심사와 해금 순서
예시: E급 기초 활동/조사 → 심사 응시 자격 → E급 입장 가능한 심사 전용 임무 → 지정 보스 완전 토벌 → 결과 보고/승급 장면 → D급 콘텐츠 개방.

현재 일반 게이트와 경계의 군주는 D급을 요구한다. E→D 심사 보스를 그 잠금 뒤에 두면 진행이 막히므로, 심사 임무 입장 조건을 일반 게이트와 분리한다. 상위 게이트 전체를 E급에 열지 않는다.

완전 토벌은 보스HP0 달성으로 정의한다. 심사용 보스도 여러 활동에 걸쳐 누적 공략할 수 있게 하고 한 번에 오래/빠르게 달리는 조건을 넣지 않는다. 레벨·장비·조사 성과가 공략을 돕는다. 심사 실패/중단 시 기존 등급은 유지한다. 실제 진행과 모의 심사 기록은 분리한다.

E→D는 첫 보스 대응, D→C는 조사와 복합 패턴, 이후 심사는 장비/콘텐츠 숙련을 확인하는 방향으로 차별화한다. 후반 등급의 의미를 초반과 동일한 토벌 횟수 증가만으로 만들지 않는다.

### 초반 보스의 후반 일반 개체 등장
사용자의 성장 체감을 위해 초반 보스와 같은 계열의 개체가 상위 지역의 일반 사건에도 등장하게 한다. 등장 시작 등급과 이야기를 연결하고, 주요 보스 원본/심사 대상/일반 개체의 식별자·HP·보상·도감 관계를 구분한다.

서사가 중요한 고유 보스는 동일 개체를 반복 부활시키기보다 분열체/잔향/동종 개체 등의 설정을 검토한다. 일반 개체 처치로 주요 보스 첫 토벌 코어나 승급 심사 완료 보상이 잘못 지급되지 않아야 한다. 기존 장비와 누적 성장으로 같은 계열을 수월하게 상대하는 체감을 주고, 실제 목표 페이스는 높이지 않는다.

## 확장 원고 · 2026-09-13

사용자는 본편을 직접 지정하기보다 작가에게 맡겨 플레이하며 즐기기를 원한다. 아래 원고는 기존 방향을 구체화한 설계이며 앱 반영은 아직 하지 않았다. 반전과 후반 제목을 일반 진행 안내에 노출하지 않는다.

- [오퍼레이터 관계 기능 설계 — 본편 반전 없음](operator-relationship-design.md): 홈 터치→화제→대사 선택→응답,5단계 호감도, 저장·재열람·기존 이용자 이관, UI·오디오·모션 요구사항.
- [관계 대본12편 — 후반 맥락 포함](operator-relationship-scenes.md): 분기 응답과 선택 기억, 개인 목표, 일상6화제, 동료/개인적인 관계 선택과 후일담.

다음 구현은 이름·장면 상태·영구 해금·퀘스트 정산을 기반으로 본편과 관계를 함께 연결한다. 본편 진행과 호감도는 별도 축이다. 스토리 열람을 운동 진행의 필수 장벽으로 만들지 않고, 관계 선택 때문에 본편 결말을 막지 않는다. 기존 이미지와 음색을 유지하면서 필요한 표정·공통 음성을 이후 제작한다.
